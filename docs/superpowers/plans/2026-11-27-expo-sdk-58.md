# Expo SDK 58 — plan

From the `expo-sdk-58` roadmap item. Sources: the [SDK 58 changelog](https://expo.dev/changelog/sdk-58) and the [SDK 57 → 58 router migration guide](https://docs.expo.dev/router/migrate/sdk-57-to-58/).

## What SDK 58 changes for this app

- **Safe areas on the web:** Expo Router no longer provides insets through `react-native-safe-area-context` on the web. `src/app/index.tsx` (`useSafeAreaInsets`), `src/components/screen.tsx` and `src/components/sheet.tsx` (`SafeAreaView`) depend on it. These carry the iPhone home-screen layout, so this is the riskiest part.
- **Async routes on by default on the web:** screens load as separate files on first open. That would add a fetch when opening Settings or History for the first time.
- **Theming exports and the forked React Navigation API** in `expo-router` were reworked. `src/app/_layout.tsx` imports `DarkTheme`, `DefaultTheme` and `ThemeProvider` from `expo-router`, and the routes use the module-level `router`.
- **The experimental web modals implementation was removed.** Settings, History and Versions use `presentation: 'modal'` and draw their own sheet, so check they still open over the timer as before.
- **React Native 0.88:** removed APIs and strict TypeScript types. The typecheck will show anything affected.
- **Testing:** `renderRouter` is now async, and `@testing-library/react-native` v14 is expected.
- **Unaffected:** `web.output` is already `"single"` (only the unset default changed), and Node 26 is supported.

## Steps

1. **Upgrade:** `npx expo install expo@^58.0.0 --fix`, then `npx expo install --check` and `npx expo-doctor`.
2. **Safe areas:** keep today's behavior by wrapping the app in `SafeAreaProvider` in `src/app/_layout.tsx`. On the web, the library reads the CSS `env(safe-area-inset-*)` values itself, which is what Expo recommends. Confirm in the SDK 58 `expo-router` source that it no longer provides one. If wrapping isn't enough, switch to CSS padding on the web only.
3. **Async routes:** opt out on the web (`["expo-router", { "asyncRoutes": { "web": false } }]`), so Settings and History open as instantly as before. Revisit with the content pages idea.
4. **Fix** whatever the typecheck, lint and tests report: theming imports, router calls, test helpers.
5. **Check:**
   - `npm run check` and a production build.
   - Drive the built site in headless Chrome: timer start and finish, both pickers, Settings, History, Versions, rotation, light and dark.
   - `npm audit --omit=dev` no longer lists `decode-uri-component`.
6. **Daniel tries the preview on his phone** before merging:
   - home screen and Safari
   - the notch and home-bar spacing, upright and sideways
   - sounds, including after switching away and back
   - the pickers and Settings
7. **Release:** a feature-sized change under the hood but nothing new for the person using the app, so a fix release (0.14.6) with the standard dependency text. Move the item to Done and merge once Daniel has tried it.
